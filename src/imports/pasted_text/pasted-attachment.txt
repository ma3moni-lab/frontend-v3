5. Email Verification

During registration:

Create user.
Generate secure verification token.
Store token securely.
Queue email.
Send through Amazon SES.
Return success immediately.

Verification link:

https://ma3moni.com/verify-email?token=<token>

The frontend will call:

POST /api/auth/verify-email/

Backend must:

Validate token
Check expiry
Verify email
Invalidate token
Return success

Tokens expire after 24 hours.

Tokens must be single-use.

6. Development Email Verification Toggle

Implement a configurable verification mode for development and production.

Environment Variables
EMAIL_VERIFICATION_ENABLED=True
EMAIL_VERIFICATION_DEV_CODE=000000
Production Mode

When:

EMAIL_VERIFICATION_ENABLED=True

The backend must:

Generate secure verification tokens or OTPs.
Send real verification emails through Amazon SES.
Require users to verify using the real code.
Reject invalid or expired verification attempts.
Development Mode

When:

EMAIL_VERIFICATION_ENABLED=False

The backend must:

Skip sending real emails.
Use the MockEmailProvider.
Accept the configured development verification code.
Default verification code:
000000
Continue the complete verification workflow exactly as production:
Verify the email.
Update the user's verification status.
Execute all post-verification business logic.
Clearly log that Development Verification Mode is active.

The frontend must continue using the exact same API endpoints in both development and production.

Example:

POST /api/auth/verify-email/

Production:

{
    "email":"user@example.com",
    "code":"583214"
}

Development:

{
    "email":"user@example.com",
    "code":"000000"
}
Security

If:

DEBUG=False

and

EMAIL_VERIFICATION_ENABLED=False

the backend should:

Log a critical warning.
Optionally refuse to start to prevent accidental production deployment.

The development verification code must never be hardcoded throughout the codebase. It must always come from environment variables.
